## What changed between v3 and v4

In **v3**, configuration lives in a single `bombadil.toml` at the root of your dotfiles directory. Per-subsystem files are pulled in via an `import` list, and each imported file declares file mappings under `[settings.dots]`.

In **v4**, there is no root config file. Bombadil discovers `dots.toml` files automatically by walking your dotfiles directory. Each subdirectory owns its own `dots.toml` with a `[dot.files]` table.

## Use the migrate command

```bash
# Preview what would be generated — nothing is written to disk
bombadil migrate ~/dotfiles --dry-run

# Write the generated dots.toml files to a separate directory
bombadil migrate ~/dotfiles --output ~/dotfiles-v4
```

`bombadil migrate` reads each file listed in the v3 `import` array, converts `[settings.dots.*]` entries to `[dot.files]` format, and writes a `dots.toml` next to each imported file — but in `--output` rather than in your live dotfiles directory.

`--dry-run` prints what would be written without touching anything. Always run it first to review the conversion before committing to `--output`.

## Before and after

**v3 layout:**

`~/dotfiles/bombadil.toml`:
```toml
dotfiles_dir = "dotfiles"

[settings]
import = ["zsh/zsh.toml", "nvim/nvim.toml"]
```

`~/dotfiles/zsh/zsh.toml`:
```toml
[settings.dots]
zshrc  = { source = "zshrc",  target = ".zshrc" }
zshenv = { source = "zshenv", target = ".zshenv" }
```

`~/dotfiles/nvim/nvim.toml`:
```toml
[settings.dots]
init = { source = "init.lua", target = ".config/nvim/init.lua" }
```

**v4 layout (generated by `bombadil migrate`):**

`~/dotfiles-v4/zsh/dots.toml`:
```toml
[dot]

[dot.files]
"zshrc"  = "~/.zshrc"
"zshenv" = "~/.zshenv"
```

`~/dotfiles-v4/nvim/dots.toml`:
```toml
[dot]

[dot.files]
"init.lua" = "~/.config/nvim/init.lua"
```

The migrator converts `target = ".zshrc"` to `"~/.zshrc"` and uses the `source` filename as the key. No other files in your dotfiles directory are touched.

## After migration: step-by-step

1. **Review** each generated `dots.toml` in `~/dotfiles-v4/`. Check that file paths and names look correct.

2. **Copy** the generated files into your live dotfiles directory, or move `~/dotfiles-v4/` into place:

   ```bash
   # Copy only the generated dots.toml files, leaving everything else intact
   find ~/dotfiles-v4 -name dots.toml | while read f; do
     rel="${f#$HOME/dotfiles-v4/}"
     dest="$HOME/dotfiles/$rel"
     mkdir -p "$(dirname "$dest")"
     cp "$f" "$dest"
   done
   ```

3. **Re-register** your dotfiles directory with Bombadil:

   ```bash
   bombadil install ~/dotfiles
   ```

4. **Sync** to apply everything. Bombadil auto-discovers all `dots.toml` files:

   ```bash
   bombadil sync
   ```

5. **Remove** the old root `bombadil.toml` and per-subsystem `*.toml` import files. They are no longer read by v4:

   ```bash
   rm ~/dotfiles/bombadil.toml
   rm ~/dotfiles/zsh/zsh.toml
   rm ~/dotfiles/nvim/nvim.toml
   ```

## Safety notes

- `bombadil migrate` **never modifies** files inside `<dotfiles-dir>`. It only writes to `--output`.
- Run with `--dry-run` first and review the output before writing anything.
- The old `bombadil.toml` import list is ignored by v4 — you can leave it in place temporarily while testing without affecting v4 behaviour.
- Variables (`[settings.vars]`), profiles, and hooks are not automatically migrated. Add them manually to the generated `dots.toml` files using the v4 schema.
